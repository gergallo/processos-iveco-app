TORRE IVECO · CONTROLE PROCESSOS IVECO
======================================
Torre de controle dos processos de containers (portos RJ/Santos → Iveco Sete Lagoas e Sada Betim):
Tabela de controle, Follow para o cliente, Painel BI, Painel 3D, Críticos, Necessidade × Follow,
Linha do tempo, Rodovias e Indicadores. Funciona no navegador e pode ser instalado como aplicativo
no computador ou no celular.

ESTRUTURA (todos os arquivos ficam na mesma pasta, sem subpastas)
  index.html             estrutura da página (visual de aplicativo: menu lateral, barra superior,
                         barra inferior no celular)
  estilos.css            aparência das tabelas, painéis e mapas
  app-shell.css          aparência do aplicativo (menu, cartões, tema claro/escuro, celular)
  shell.js               comportamento do menu, título das telas, tema e menu "mais opções"
  app.js                 lógica do controle (importação, cálculos, painéis, mapas, 3D, resumos)
  servicos.js            banco de dados (Supabase na nuvem ou armazenamento local) e downloads
  instalacao.js          instalação como aplicativo e backup
  config.js              endereço do banco na nuvem (deixe em branco para modo local)
  sw.js                  funcionamento offline
  manifest.webmanifest, icon-*.png, apple-touch-icon.png   ícones do aplicativo
  CONFIGURAR-NUVEM.sql   estrutura do banco (Supabase)
  Bibliotecas de terceiros (não editar): three.min.js e OrbitControls.js (MIT),
  xlsx.full.min.js (Apache-2.0), jspdf.umd.min.js (MIT), supabase.js (MIT).

MODOS DE USO
  1) Modo local (sem nuvem) — config.js com url e chave vazias.
     Os dados ficam no navegador de cada computador. Use o botão Backup para levar os dados
     de um computador para outro. Não depende de nenhum serviço externo.
  2) Modo nuvem (equipe compartilhando a mesma base, em tempo real) — Supabase.
     a. Crie um projeto em supabase.com (de preferência com a conta da empresa).
     b. SQL Editor → cole o conteúdo de CONFIGURAR-NUVEM.sql → Run.
        Troque o e-mail no final do arquivo pelo(s) e-mail(s) de quem pode editar.
     c. Authentication → Users → Add user: cadastre quem vai acessar (e-mail e senha).
     d. Connect (ou Settings → API): copie a URL do projeto e a chave "publishable/anon"
        e preencha o config.js. Nunca use a chave "service_role/secret".

PUBLICAÇÃO
  Qualquer servidor de páginas estáticas serve (servidor interno da empresa, Azure Static Web
  Apps, IIS, GitHub Pages da organização etc.): basta copiar todos os arquivos para a mesma pasta.
  Para testar no próprio computador, abra a pasta com um servidor local
  (ex.: no VS Code, extensão "Live Server"); abrir o index.html direto do disco não ativa o modo offline.

ATUALIZAÇÕES
  Ao alterar qualquer arquivo, aumente a versão em sw.js (controle-iveco-v35 → v36 ...).

SERVIÇOS EXTERNOS USADOS
  Supabase (somente no modo nuvem) · Open-Meteo (clima em tempo real, opcional)
  · links para WhatsApp, Waze e Google Maps (só quando o usuário clica).

PRIVACIDADE
  Não publique planilhas, backups ou prints com dados junto com os arquivos do aplicativo.

USO NO DIA A DIA
  Computador: menu lateral à esquerda (botão no rodapé recolhe o menu só para ícones; o botão
  da lua/sol alterna tema claro/escuro). Botão "⋯" no topo: Exportar Excel, Backup, ocultar o
  resumo do dia e instalar como aplicativo.
  Celular: barra inferior com Tabela, Follow, BI, 3D e Menu (abre todas as telas).
